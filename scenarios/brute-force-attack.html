Brute Force Attack

When this alert appears, the first thing I want to determine is whether this is normal failed login activity, password spraying, or an actual brute force attack attempting to gain unauthorized access. Failed logins happen regularly in every environment, so the investigation should focus on login patterns, attacker behavior, and whether any account was eventually compromised.

Important: The main goal is to identify if the attacker successfully authenticated after repeated attempts.

Step 1 — Validate The Alert


I would begin by reviewing the authentication logs related to the alert. At this stage, I want to understand which account was targeted, where the login attempts came from, and whether the activity involved a single user or multiple accounts. Brute force attacks usually generate a high number of failed logins within a short timeframe.

Insight: The timing and volume of attempts often reveal whether this was automated activity.

Main things to verify:

  • Targeted username
  • Source IP address
  • Number of failed attempts
  • Login timestamps
  • Authentication method


Where to look:

  • SIEM authentication logs
  • Active Directory logs
  • VPN logs
  • Firewall logs
  • Cloud identity logs

Step 2 — Identify The Attack Pattern


After validating the alert, I would analyze the login behavior itself because different patterns indicate different attack techniques.

Attack Pattern: A traditional brute force attack usually targets one account with many password attempts, while password spraying targets multiple accounts using a few common passwords.

This stage helps determine attacker intent and potential risk level.


Main things to focus on:

  • Single account vs multiple accounts
  • Rapid login attempts
  • Common password usage
  • Multiple source IPs
  • Geographic anomalies


Where to look:

  • Authentication logs
  • Azure AD sign-in logs
  • VPN authentication events
  • IDS/IPS detections

Step 3 — Determine If Login Was Successful


Critical Phase: This is the most important part of the investigation. Many brute force attempts fail completely, but if the attacker eventually succeeds, the incident becomes an account compromise investigation instead of a simple login attack alert.

I would carefully review successful logins immediately after failed attempts from the same IP address or device.


Main things to focus on:

  • Successful authentication after failures
  • MFA bypass attempts
  • New device logins
  • Unusual login locations
  • Session creation activity


Where to look:

  • Authentication success logs
  • MFA logs
  • VPN session logs
  • Cloud access logs
  • Identity monitoring dashboards

Step 4 — Investigate Post-Authentication Activity


If a successful login occurred, I would immediately investigate what the attacker did after gaining access. Attackers often attempt mailbox access, privilege escalation, internal reconnaissance, or lateral movement shortly after compromise.

Shift in Focus: At this stage, the investigation shifts from login monitoring to account misuse detection.

Main things to focus on:

  • Mailbox rule creation
  • Sensitive file access
  • Administrative actions
  • Internal network access
  • New account creation


Where to look:

  • Email audit logs
  • File access logs
  • Active Directory logs
  • EDR telemetry
  • Cloud audit trails

Step 5 — Check Environment-Wide Activity


Hunting Strategy: Brute force attacks rarely target only one account. Attackers usually scan multiple users, services, or exposed authentication portals.

I would search the environment for similar login attempts against other accounts or systems using the same source IP or indicators. This helps determine whether the attack was isolated or part of a larger campaign.


Main things to focus on:

  • Multiple targeted accounts
  • Repeated attacker IPs
  • VPN gateway attacks
  • Password spraying behavior
  • Shared indicators across systems


Where to look:

  • SIEM correlation searches
  • Firewall logs
  • Identity management platforms
  • Threat intelligence feeds

Step 6 — Containment And Response


If no login succeeded, containment may only require blocking the source IP and monitoring the targeted account. However, if compromise is suspected, password resets and session revocation become immediate priorities.

Accounts with administrative privileges should always be treated with higher urgency because successful brute force against privileged users can quickly lead to wider compromise.


Main response actions:

  • Block malicious IP addresses
  • Reset compromised passwords
  • Revoke active sessions
  • Enforce MFA
  • Lock or monitor targeted accounts

Final Investigation Goal


The investigation should answer these questions:

  1. Was this a real brute force attack or normal failed login activity?
  2. Did the attacker successfully authenticate?
  3. Which accounts were targeted?
  4. Was post-login malicious activity observed?
  5. Are additional systems or accounts affected?

Once those answers are confirmed, the incident can be properly contained and monitored for continued attack activity.
